## 6.11 Disguise (camouflage)

Taken over from OpenModularTurrets on the main branch (`../../OMTTeam1.21.11/OpenModularTurrets`, `camo/`); on this branch the lights use OMLib's camouflage (since 2026-10-25, requested by the user), like OMT's turret bases and OMPD's camouflage trap.

- **Which lights:** the electric, carbon and UV floodlights (`FloodlightBlock.supportsCamo`). Not the panel lights (thin, no full face to disguise) and not the cube light (no front, it would vanish completely).
- **Host:** `FloodlightTileEntity` implements OMLib's `ICamoSupport`: camouflage enabled on those lights, no light sliders (`supportsLight` false), anyone who may open the light's GUI may set the disguise (`canSetCamo` true; the lights have no owner); `getCamoState` is the disguise or the light's own default state, and `setCamoState` with the light's own block removes the disguise.
- **Valid disguises:** the light's OMLib `DisguiseRules` (`FloodlightTileEntity.getDisguiseRules`): OMLib's `util.camo.CamoRules` without see-through blocks (a full block, drawn from a normal model, without a tile entity; `isFullBlock` is the default state's `isOpaqueCube`, so glass, which would show holes into the world, is refused), with OML's refusal message and slot hint (`message.openmodularlighting.camo_invalid`, `tooltip.openmodularlighting.camouflage_slot`). An invalid disguise read from NBT is dropped.
- **Setting it:** the Camouflage button in the floodlight GUI (`FloodlightGui`, only if `FloodlightContainer.hasCamoButton`) sends OMLib's `MessageOpenCamoMenu`; the server opens OMLib's camouflage menu (`ContainerCamo` / `CamoGui`): clicking its slot with a block sets the disguise, with an empty cursor removes it, shift-clicking a block sets it too. Its Back button returns to the light's GUI: the light has a parent menu (`hasParentMenu`), OMLib's `MessageCamoBack` lets the server reopen it (`openParentMenu` → `FloodlightBlock.openGui`). The Camouflage button sits at 88,38 (80 × 18) with a tooltip, as on the main branch.
- **Data:** part of the settings (saved, sent in the update tag, kept on the dropped item) in OMLib's format (`camoBlockRegName`, `camoBlockMeta`, `BlockUtil`); the `camo` compound of 1.0.0-beta.6 and older is still read.
- **Rendering:** the client wraps the models of the lights that support camouflage (`client.camo.CamoModels` / `CamoModel`, §5). With a disguise they emit the disguise's model (its own render layer, ambient occlusion and tint) and, of the light's own model, only the **lamp quads**: an extra front-face element in `models/block/floodlight.json` with `tintindex: 1` and the `#lamp` texture (`<light>_lamp[_on].png`, the ring and disc cut out of the front texture with the rest transparent). Without a disguise the overlay lies over the identical pixels of the front face, so the floodlights are in the cutout layer. Cut the lamp textures again if a front texture changes.
  OMLib's `CamoBakedModel` is not used: it draws the disguise only, without the lamp on top (it would need an overlay hook in OMLib).
- **Tint:** the lamp keeps the dye colour (`FloodlightTint`); `FloodlightTint` forwards every tint index other than 1 to the disguise's colour.
- Hwyla, the pick-block item and the break particles still show the real floodlight (the disguise is cosmetic, unlike OMT's hidden turrets).
